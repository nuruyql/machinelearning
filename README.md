## Цель работы

Цель практической работы — построить пайплайн предобработки данных с использованием `Pipeline` и `ColumnTransformer`, а также избежать утечки данных между train и test.

## Датасет

Используется датасет `donors.csv`.

Размер датасета:
- 52 строки
- 13 признаков

## Классификация признаков

### Числовые признаки
- `family_size`
- `size_bytes`

Для числовых признаков используется:
- `SimpleImputer(strategy="median")` для заполнения пропусков;
- `StandardScaler` для масштабирования.

Медиана выбрана потому, что она менее чувствительна к выбросам, чем среднее значение.

### Категориальные признаки
- `author`
- `license`
- `behaviour_family`
- `family_evidence`
- `payload_included`
- `payload_format`

Для категориальных признаков используется:
- заполнение пропусков отдельной категорией `missing`;
- `OneHotEncoder(handle_unknown="ignore")`.

Отдельная категория `missing` позволяет сохранить информацию о том, что значение изначально отсутствовало.

### Исключённые признаки
- `donor_id` — идентификатор;
- `source_url` — URL;
- `main_py_sha256` — hash;
- `payload_b64` — закодированные данные;
- `verified` — не используется в текущем пайплайне.

## Train / Test Split

Перед обучением пайплайна данные разделяются:

- Train — 80%
- Test — 20%

Разделение выполняется до операций, которые вычисляют статистики по данным.

## ColumnTransformer

Для разных типов признаков используются разные преобразования:

- числовые → заполнение медианой + StandardScaler;
- категориальные → заполнение категорией `missing` + OneHotEncoder.

Все этапы предобработки объединены в `Pipeline` и `ColumnTransformer`.
